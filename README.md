## My engineering rules

| Principle | What it means in practice |
|---|---|
| **Make it understandable** | Clear names, small steps, setup instructions someone else can follow. |
| **Verify before claiming** | Separate what works, what is tested, and what is still a limitation. |
| **Build for a person** | Start with the user problem; treat visual polish as part of usability, not a substitute for it. |
| **Keep learning visible** | Improve projects incrementally and explain what changed and why. |
